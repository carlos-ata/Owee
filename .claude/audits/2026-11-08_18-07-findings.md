## F1 🔴 Self-check makes `DebtConfirmUseCase` a no-op safeguard — left as-is
[debt-confirm.use-case.ts:25](../../src/modules/debt/application/use-cases/debt-confirm.use-case.ts#L25)

```ts
if (resDebtExists.creatorId !== user.id) {
  throw error.forbidden(...);
}
```

The confirming user is compared against `creatorId` — the same user who just created
the debt in `DebtCreateUseCase`. Since the creator always satisfies this check, the
guard can never reject the person who registered the debt: the "confirm" action cannot
meaningfully fail for its own author. No action taken on this per explicit instruction —
tracked, not touched.

## F2 🟠 Dead existence checks, plus two narrower race-condition guards leaking an English, wrong-layer error
Full trace of every call into `PgSqlDebtRepository`
([pgsql-debt.repository.ts](../../src/modules/debt/infrastructure/repositories/pgsql-debt.repository.ts)):

| Repository method | Guard | Reachable? |
|---|---|---|
| `findById` (called from `debt-cancel` and `debt-confirm` use cases before `cancel`/`confirm`) | `if (!debt) throw error.notFound("Debt not found")` | **Never** — the port declares `Promise<Debt>` (no `null`), and every caller's own `if (!resDebtExists) throw ...` right after it is therefore unreachable too. Two dead guards for every one live throw. |
| `cancel` | `if (!debt) throw error.notFound("Debt not found")` after `.update(...)` | Only on a **race condition** — the row existed when `findById` ran a moment earlier in the same use case, but could disappear between that check and this `update` (e.g. concurrent cancellation). Narrow, but real. |
| `confirm` | same pattern as `cancel`, same race window | Same as `cancel`. |

So this isn't one dead branch, it's three instances of the same anti-pattern with two
different reachability profiles:

- The `findById`-driven guards in `debt-cancel.use-case.ts:22` and
  `debt-confirm.use-case.ts:22` are **fully dead** — they can never execute because
  `findById` throws before returning falsy.
- The `cancel`/`confirm` methods' own internal guards **can** fire, but only on a race,
  and when they do, the client sees `"Debt not found"` in English, thrown from
  infrastructure — not the use case's own `"La deuda no existe"` / `"Deuda no
  encontrada"` in Spanish, which is the layer the architecture assigns that decision to.

Net effect even outside the race case: the dead guards give a false sense that the use
case owns the not-found decision, when in practice `findById` already decided it,
in the wrong language, one layer down.

## F3 🟠 `config.isProduction` can never be `true` — what to change (not applied)
[config.ts:10](../../src/config/config.ts#L10):

```ts
isProduction: process.env.NODE_ENV === "true",
```

`NODE_ENV` is conventionally `"production"`, `"development"`, or `"test"` — never the
literal string `"true"`. Fix: compare against the real value.

```ts
isProduction: process.env.NODE_ENV === "production",
```

This flag drives [error.ts:11-16](../../src/infrastructure/middleware/error.ts#L11):
with the current comparison, `isProduction` is always `false`, so stack traces always
ship in every error response, in every environment. Not applied — flagged for the user
to apply.

## F4 🟠 CORS has no origin/credentials configuration
[app.ts:24](../../src/app.ts#L24): `app.use(cors())` with no options. Better Auth's
session relies on a cookie; browsers won't attach a cookie to a cross-origin request
unless the response carries `Access-Control-Allow-Credentials: true`, which bare
`cors()` never sends. Any frontend on a different origin than the API cannot maintain a
session as currently configured.

## F5 🟠 `pnpm build` cannot produce a runnable build
`tsconfig.json` sets `noEmit: true`; the `build` script is plain `tsc` (emits nothing
under `noEmit`), yet `start` runs `node dist/server.js`. There is currently no script
path that produces `dist/`.

## F6 🟡 `.env` path is resolved from `process.cwd()`
[config.ts:4-6](../../src/config/config.ts#L4): `dotenv.config({ path:
path.resolve(process.cwd(), "src/config/.env") })`. Starting the process from any
directory other than the repo root breaks env loading silently (`process.env.X` is
`undefined`, not an error).
