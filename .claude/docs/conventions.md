# Conventions — Owee

Code-level rules. Some are **not written anywhere but already practiced** in the repo;
others fix inconsistencies tracked in `audits/findings.md`. When touching a file that
violates one, align it if it's cheap; otherwise log it in `audits/findings.md`.

---

## 1. File names

Everything in **kebab-case**, with a suffix identifying the role:

| Role | Pattern | Example |
|---|---|---|
| Entity | `<entity>.entity.ts` | `debt.entity.ts` |
| Port (repo interface) | `<module>.repository.ts` | `debt.repository.ts` |
| Repo implementation | `<technology>-<module>.repository.ts` | `pgsql-debt.repository.ts` |
| Use case | `<entity>-<action>.use-case.ts` | `debt-confirm.use-case.ts` |
| Application DTO | `<entity>-<action>.dto.ts` | `debt-create.dto.ts` |
| Zod schema | `<entity>-<action>.schema.ts` | `debt-create.schema.ts` |
| HTTP → app mapper | `<entity>-<action>-to-domain.mapper.ts` | `debt-create-to-domain.mapper.ts` |
| Domain → DB mapper | `<entity>-<action>-to-db.mapper.ts` | `debt-create-to-db.mapper.ts` |
| DB → domain mapper | `<entity>-to-domain.mapper.ts` | `debt-to-domain.mapper.ts` |
| Response DTO | `<entity>-<action>-response.dto.ts` | `debt-generic-response.dto.ts` |
| Row types | `<x>.types.ts` | `debt.types.ts` |
| Controller | `<module>.controller.ts` | `debt.controller.ts` |
| Router | `<module>.router.ts` | `debt.router.ts` |

**Order is `<entity>-<action>`, not `<action>-<entity>`**: `debt-create`, not
`create-debt`. That way every file for an entity sorts together.

## 2. Symbol names

- **Classes** in `PascalCase`. Adapters carry a technology prefix:
  `ExpressDebtController`, `PgSqlDebtRepository`. Domain and application classes
  **don't**: `Debt`, `DebtCreateUseCase`.
- **Port interfaces** prefixed with `I`: `IDebtRepository`. Other interfaces (props,
  DTOs, `Deps`) have **no** `I`.
- **Mapper functions** in `camelCase` ending in `Mapper`: `debtCreateToDbMapper`.
- **Zod schemas** in `camelCase`; their inferred type shares the name in `PascalCase`:
  ```ts
  export const debtCreateSchema = z.object({ /* ... */ });
  export type DebtCreateSchema = z.infer<typeof debtCreateSchema>;
  ```
- **DTOs** end in `DTO`: `DebtCreateDTO`.
- **Domain data interfaces**: `<X>Props` (to rehydrate), `New<X>Data` (to create),
  `<X><Action>Data` (for a transition): `DebtProps`, `NewDebtData`, `DebtConfirmData`.

## 3. Exports

- **Classes:** `export default`. One class per file.
- **Mappers, schemas, types, DTOs, middlewares:** named exports.
- **Routers:** `export default function create<Module>Router(controller)`. The router
  is a **factory that receives the controller** — it never resolves the container
  itself. (`hello-world.routes.ts` does `new Controller()` inline — old pattern, don't
  copy it.)

## 4. Imports

- Always the aliases from `package.json`, never `../../..`:
  `#config/*`, `#container/*`, `#prisma/*`, `#routes/*`, `#domain/*`,
  `#infrastructure/*`, `#docs/*`, `#modules/*`, `#auth/*`, `#debt/*`.
- **The specifier ends in `.js`** even though the file is `.ts`.
- Inside a module, use its short alias (`#debt/...`), not `#modules/debt/...`. A new
  alias per module is added to `imports` in `package.json` when the module is created.
- `import type` for everything used only as a type (`verbatimModuleSyntax`). In
  controllers, use cases are imported with `import type` because they're only used as a
  type — the instance arrives through `deps`.
- Block order, separated by a blank line: external library types → external libraries
  → domain → application → module infrastructure → errors.

## 5. TypeScript

`tsconfig.json` imposes restrictions that shape how code is written:

- `erasableSyntaxOnly: true` → **no** parameter properties, `enum`, `namespace`, or
  `declare` on class fields. For fixed value sets use a literal union
  (`export type DebtStatus = "A" | "I"`) + an `as const` object if you need the values.
- `verbatimModuleSyntax: true` → explicit `import type`.
- `strict: true` → no implicit `any`. If you genuinely need `any` (e.g. `wrapErrors`),
  keep it scoped to infrastructure.
- `noEmit: true` → `tsc` only typechecks.
- `rewriteRelativeImportExtensions: true` + `moduleResolution: "bundler"` → this is what
  allows writing `.js` in import specifiers.
- No `!` (non-null assertion) in domain or application. If a value can be missing,
  model it as `| null` and validate in the use case.

## 6. Domain data types

| Concept | TS type | Why |
|---|---|---|
| Money amount | `string` | `Numeric(12,2)` in Postgres; `number` loses precision. Validated with a regex in Zod and cast to `Numeric<12,2>` only in the `*-to-db` mapper |
| Date / time | ISO 8601 `string` | the contract uses `TimestamptzString`; the domain never handles `Date` |
| User id | `string` | generated by Better Auth |
| Debt / payment id | `number` | `Int @default(autoincrement())` |
| Record state | `"A" \| "I"` | active / inactive (soft delete) |
| Confirmation flag | `boolean \| null` | `null` = awaiting the counterparty's response |

`new Date().toISOString()` is called **inside the entity's static methods**
(`create`, `confirm`, `cancel`), never in the controller or the repository.

## 7. Validation (Zod 4)

- One schema per action, in `infrastructure/http/schemas/`.
- A schema validates **one** part of the request. The `validation` middleware accepts
  `{ body }`, `{ query }`, or `{ params }`.
  See `audits/findings.md` for a known gap in this middleware before relying on it for
  more than one key at a time.
- `params` and `query` always arrive **as `string`**. For a numeric id use
  `z.coerce.number().int().positive()`, never `z.number()` (it always fails).
- The body is **nested under a resource key** (`{ user: {...} }`, `{ debt: {...} }`).
  Keep that shape; the `*-to-domain` mapper flattens it.
- Error messages in Spanish — they're user-facing, and the app's users are
  Spanish-speaking. (Everything in this `.claude/` guide stays in English regardless.)
- The schema's inferred type is the **only** valid input for the `*-to-domain` mapper.
  Never type an HTTP mapper with `any` or with the entity.
- Zod validates **shape**, not business rules.

## 8. Errors

Use the factory in `#domain/errors/app-error.js`:

```ts
import { error } from "#domain/errors/app-error.js";
throw error.notFound("La deuda no existe");
throw error.forbidden("No tienes permitido realizar esta acción");
```

- **Throw from the use case.** It's the layer that knows the reason.
- The repository **does not throw HTTP errors**: if it finds nothing, it returns `null`
  and the use case decides. (See `audits/findings.md` for a repository that currently
  throws instead.)
- Messages are user-facing text (in Spanish, per the app's audience) — never leak
  internals (SQL, other users' ids).
- Codes to use:
  | Situation | Factory |
  |---|---|
  | Invalid request shape | emitted by `validation` (400) |
  | Business rule violated | `error.badRequest` / `error.unprocessableEntity` |
  | No session / invalid cookie | `error.unauthorized` |
  | There's a session but the resource isn't yours | `error.forbidden` ⬅ **not** `unauthorized` |
  | Resource doesn't exist | `error.notFound` |
  | Incompatible state (already confirmed, already settled) | `error.conflict` |

Fixed middleware chain order (declared in `app.ts`, don't reorder):
`notFound` → `logErrors` → `wrapErrors` → `errorHandler`.

## 9. HTTP response shape

Always via `res.success(data, statusCode)` (injected by `responseExtender`):

```json
{ "statusCode": 201, "data": { "id": 12 }, "error": null }
```

Error:

```json
{ "error": { "statusCode": 404, "error": "Not Found", "message": "La deuda no existe" }, "data": {} }
```

- **Never** `res.json(...)` or `res.send(...)` directly in a controller.
- `data` always comes from a **response DTO**, never the raw entity.
  A response DTO declares its interface and the mapper returns it typed:
  ```ts
  export interface DebtGenericResponseDTO { id: number }
  export function debtGenericToResponseMapper(data: Debt): DebtGenericResponseDTO {
    return { id: data.id };
  }
  ```
- Codes: `201` create, `200` read/update, `204` no body (pass `null` as data).

## 10. HTTP and routes

- Resource in **singular**, same as the module: `/api/v1/debt`.
- State transitions as a sub-resource with `PATCH`:
  `PATCH /debt/:id/confirm`, `PATCH /debt/:id/settle`.
- `DELETE /debt/:id` exists but performs a **soft delete** (`status: "I"`). No business
  entity is ever physically deleted.
- `authenticate` goes **before** `validation` in the middleware list.
- Never accept an "actor" user id in the body: it comes from `res.locals.user`.

## 11. Authentication

- Better Auth with a session cookie. The client must send `credentials: "include"`.
- `authenticate` calls `GetSessionUseCase` with `req.headers.cookie` and stores the
  `User` entity in `res.locals.user`.
- `res.locals` typing is declared via `declare global` (same pattern as `res.success`
  in `response.ts`). See `audits/findings.md` for the current typing gap and the exact
  fix.
- `password` **never** leaves the repository or appears in a response DTO (mappers set
  it to `""`; keep that).

## 12. Configuration

- `src/config/config.ts` is the **only** file that reads `process.env`. A new
  environment variable gets added there and consumed from the exported object.
- `.env` lives at `src/config/.env` and is not committed.

## 13. Documentation

Every new or changed endpoint gets documented with OpenAPI JSDoc on its route, inside
`*.router.ts`. Full procedure and templates: skill `swagger-endpoint-docs`.

## 14. Comments

The repo's code barely has comments, and that's fine — names already carry the intent.
Comment only the non-obvious *why* (a Postgres constraint, a Prisma RC workaround).
**Don't** leave commented-out code: delete it.
